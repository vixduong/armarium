# armarium
- Gate: `bin/check` runs every self-test plus the config checks (settings paths, pointers, user-only skills). `.githooks/pre-commit` runs it; enable per clone with `git config core.hooksPath .githooks`.
- `claude/common/` (shared) plus one OS overlay mirror `~/.claude`. macOS/Linux: `common/` and `unix/` are symlinked there, so an edit is live at once. Windows: `claude/windows/install.ps1 -Apply` copies `common/` then `windows/`, so re-run it after an edit.
- A gate edit changes verdicts: `bin/hook-diff` prints every command of `bin/hook-corpus.jsonl` that the work tree judges differently from `HEAD` (`-` reads rows from stdin). Run it before a review, give its output to the reviewer, and add the rows a review tried.
- A hook under `claude/common/` or `claude/unix/` is live in every open session while you edit it, and one that fails to start lets every call through. A change past a few lines: copy the hook, its `test_*.py` and the `path_only.py` it may import to the scratchpad, work and test there (the test runs the hook beside it), then write the real file once.
- Windows: CI (`.github/workflows/check.yml`, `windows-latest`) is the only Windows run. A Windows-only change → with the user's OK, push a branch or `gh workflow run check.yml --ref <branch>`, then `gh run watch`.
- Test seams: a hook (JSON on stdin) or a `claude/common/bin/` script (argv) is tested as a process (→ exit code, stdout, stderr) by the `test_*.py` beside it; `pi/armarium-pi/index.ts` through the fake pi in `pi/test_armarium_pi.py`. A new test goes at one of these two.
- `pi/AGENTS.md` is the pi edition of `claude/common/CLAUDE.md`, in pi's tool, agent and skill names. A rule change in one goes into the other in the same commit.
